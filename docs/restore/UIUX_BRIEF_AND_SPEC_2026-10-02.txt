The UI/UX prep package is done: nine design records under `G:\UNNAMED_HISTORY\CLAUDE_UI_UX_PREP_2026-10-02\`. I recommend Direction A, and the visual language is ready to implement.

Your HUD note changed the recommendation. The C4 stills show the old plain-text HUD, but the live demos run the finished production HUD (the DS_PHASEB lineage, used at every quality tier). The menu language is now built out of that HUD, and the audit records its traits.

1. **Surfaces audited:** all twelve C4 screens, from source and the final native captures (an earlier run for a populated Building screen). The production HUD was read from its source and final captures, and the approved style direction (Player Journey doc 09 §9) and the old DS popup lane were used for reference.
2. **Strongest problems:**
   - Screens cover the HUD's health/stamina bars, and on Help the combat log, while the world keeps running, so a player can be hit without seeing it.
   - Eight screens are one block of text, with actions detached from what they act on. Character's +1 buttons sit below everything and can fall off-screen.
   - Skills prints raw content IDs, repeats the same "untrained" sentence ten times, and shows no Known/Ready/Blocked state.
   - Four unrelated panel sizes and positions, no shared theme, and empty screens that look broken.
   - No visible keyboard focus, and Inventory buttons can't take focus at all.
3. **Direction A, "Field Instrument":** the HUD's larger, calmer sibling. Same dark translucent panels, thin grey border lines, off-white text, Barlow fonts, key caps, chips and segmented gauges. The warm ember accent is kept for focus only. Science-fantasy comes through measurement: magic pools sit on the same instrument as health.
4. **Direction B, "Survey Glass":** cool graphite panels, a green-teal accent and a chamfered corner. It is more distinctive, but it conflicts with the existing HUD and breaks the approved "warm focus colour, no ornamental frames" direction.
5. **Recommended: A.** It is one product with the HUD, consistent with the approved direction, and the cheapest to build. The one rule that stops it drifting into generic dark fantasy: ember marks only focus, the main action and things that need the player.
6. **Design system:**
   - **Placement:** every screen sits in the screen area the HUD leaves free, x 384–1536 by y 128–848 at 1920×1080. Health, the combat log and notices stay visible.
   - **Panel sizes:** 640 / 880 / 1152 wide, plus a two-column 1152×720 for dense screens.
   - **Type and spacing:** 16 px minimum text size, and one spacing scale (4 to 48 px).
   - **Colours:** the HUD's colour set plus two additions, a secondary surface and a green for "available/ready".
   - **States and rows:** full button states, and one shared row design for items, skills, factions, effects, companions, pieces and saves.
7. **System Menu:** a primary Continue with default focus, then three columns: You / The World / System. Each entry shows its key. Quit is set apart, and a quiet "THE WORLD GOES ON" line confirms nothing has stopped. The menu's data model is unchanged.
8. **Character:** three columns under a name/level/XP band, with no tabs.
   - **Left, attributes:** a +1 button beside each value while points are unspent.
   - **Middle:** derived stats in an aligned grid, plus active effects and standing.
   - **Right:** equipped items, top skills with progress, and recently learned knowledge with where it came from.
9. **Skills:** a discipline list beside a detail pane, buildable without a graph framework. Known/Ready/Blocked labels and per-requirement tags show exactly why something is blocked, plus where it was learned. No points and no costs anywhere. A threshold ruler, then a full discipline map, come later.
10. **Other screens:**
    - **Reputation:** cards with standing as the most prominent thing on each.
    - **Effects:** live countdown bars in seconds.
    - **Companions:** Follow/Wait inside each companion's card.
    - **Building:** a piece list with that piece's own actions, and a confirm step on Take down.
    - **Settings:** label, control and value on one row, with the duplicate summary removed.
    - **Inventory:** joins the family and becomes keyboard reachable.
    - **Journal:** Active / Done / Failed groups, with the HUD tracker's bullets.
    - **Save/Load:** backup copies grouped under their slot, and a line saying how saving works.
    - **Help:** keys drawn as key caps, with developer controls demoted.
11. **Empty states:** a short head, the game's existing sentence and an optional key hint. The panel shrinks to fit instead of showing a large blank box.
12. **Navigation and focus:** close hints are key caps (`[K] [ESC] CLOSE`). Keyboard focus is an ember outline, distinct from the selected-row style. Every screen sets a default focus and every action is focusable. No hotkeys or controller bindings are added, but the layouts are ready for a controller.
13. **HUD relationship:**
    - **Shared:** fonts, accent colours, border style, pool colours, icon frames and key caps.
    - **Deliberately different:** menus are more opaque, one size step larger, denser and centred, where the HUD is peripheral.
    - **Future HUD notes (recorded, not changed):** the interaction prompt can show a raw instance ID, and some HUD labels are below the 16 px floor.
14. **Implementation priorities:**
    - **First (high value, low risk):** theme, fonts, the shared frame and placement on all twelve screens, the System Menu, Settings, empty states, Help, Inventory and Save/Load.
    - **Then (moderate risk):** rebuild Skills, Character, Building, Companions, Effects, Journal and Reputation from the data the models already provide.
    - **Where:** I recommend building on your combined C4 + visual checkout so the menus use the HUD's own style file. The C4 candidate has neither those fonts nor that style file yet.

# 02 - The UI design system: Direction A, "Field Instrument"

## 1. The recommendation and why

**Direction A.** The production HUD already defines Otherreach's interface identity, through its soot surfaces, iron hairline, bone text, ember focus, brass earnings, Barlow type, key caps, chips, framed icon slots and segmented gauges. The owner approved that direction in doc 09 §9 ("a thin iron-grey rule line, a warm focus colour"), and a blind review preferred it over the classic HUD in every run. A menu language that grows out of it costs least, can never drift into a second identity, and makes the HUD and the menus read as one product in different contexts. Direction B is more distinctive, but it would need the HUD retuned and it breaks the approved direction (`01`, side by side).

One rule keeps A from sliding into generic dark-fantasy amber: **ember means "this needs you, or has your focus" - nothing else.** Section heads are brass, values are bone, surfaces are neutral soot.

## 2. How this visual language relates to the existing HUD

## 9. Empty states

An empty screen says what would be here, why it is empty, and how it fills. It looks finished.

Rules:

3. **The existing sentences are kept.** They are good, honest and in the world's voice. The heads are new, short and neutral; hints marked *proposed* are new copy the owner can strike.
4. **Partial emptiness is a quiet line inside its section**, not a sheet-level empty state (for example "No conflicts - every piece the audit looked at is sound" in `Lichen` with a left bar).
5. **No illustration, no big icon.** The tick rule above the head is the only ornament.

## 10. Input, navigation and focus

The existing strategy is kept: direct keys for Character (K), Skills (P), Inventory (I / Tab), Journal (J), Save/Load (L) and Help (F1); everything else through the System Menu (Escape). No new hotkeys and no controller bindings are added.

Visual rules:

| Need | Treatment |
|---|---|
| Shortcut hints | The HUD key cap, always read live from the InputMap (`HelpPanel.Key`), never typed. In System Menu rows, at the right edge. |
| Back / close | Right end of the title bar: the screen's own key cap (if it has one), then `ESC`, then the word `CLOSE` in `Muted` capitals. Menu-only screens show `[ESC] CLOSE`. The prose hints in titles ("[K] close", "[L] or Escape: back to the game") go. |
| Selected control | The selected row state: ember tint and left bar |
| Keyboard focus | The 2 px ember outline. Focus and selection are distinct, so a focused, unselected row and a selected, unfocused row never look alike. |
| Default focus | Every screen grabs focus on open: System Menu → Continue; list/detail → the first list row (or the most useful one, `05`); Settings → the first control; Save/Load → the newest save's Load. |

Structural rules, so a controller can be added later without relayout:
- Every actionable control has `FocusMode.All`. Today's Inventory buttons (`FocusMode.None`) change.
- Lists are single vertical chains. Grids have explicit focus neighbours. Moving right from a list row enters its detail; moving left returns.
- `ScrollContainer.FollowFocus = true` everywhere, so focus never leaves the view.
- Nothing is only available on hover. Tooltips may repeat information, never hold it.
- Every action is reachable by focus plus accept.
- No horizontal scrolling.

Escape keeps its accepted C4 behaviour in the first implementation: it closes the current screen back to play, and with nothing open it opens the menu. "A menu-launched screen returns to the System Menu on Escape" is an open UX option for the owner (`08`). No navigation stack is introduced without that decision.

## 11. Copy rules for presentation

- Nothing implies stopped time: no "Paused", no "Resume" label (the model already says Continue), no frozen timers. Live timers keep counting in Effects and Companions.
- No raw content IDs, instance IDs, slot keys or world coordinates in player-facing rows. Where a model string embeds them (the technique refusal), the structured fields it already exposes are shown first, and the authority's sentence second, verbatim (`05`).
- Seconds, not ticks.
- Developer explanations ("Phase 1", "the authority's answer") move into hint lines. Rewording them is a separate copy pass that changes model strings and their tests, for the owner to approve.

## 12. Motion

Optional, and minimal: a 120 ms fade and 8 px rise when a sheet opens, and 80 ms on close. No idle animation, except that live gauges (effect time, a downed countdown) move because the world moves.

# 01 - Two visual directions

Both directions present the same twelve surfaces with the same functionality. Neither changes a command, a model or a rule. Both were judged against the production HUD (`00` "The HUD as it actually runs"), and against the owner-approved style direction in Player Journey doc 09 §9: "Dark translucent panels, clear sans-serif type ... No parchment, no neon, no ornamental frames ... a thin iron-grey rule line, a warm focus colour."

## Direction A - "Field Instrument" (grown out of the production HUD)

### Visual description

The menus are the HUD's bigger, calmer sibling. They use the same soot surface, iron hairline, bone text, Barlow and Barlow Condensed, ember key caps and small-capital labels. They are more opaque, set at a larger scale, and laid out in grids and columns instead of corner strips.

The science-fantasy reading comes from instrumentation rather than decoration. Numbers are readouts: tabular figures, a muted small-capital label beside each bone value, the way the HUD's pools panel already reads. Progress is a segmented gauge with tick marks, the HUD's gauge at management scale. The frame carries one quiet mark taken from the compass bezel: short tick marks on the title rule. Magic is not set apart in a separate style. Focus blue and Strain violet are channels on the same instrument as Health red, which is the "one reality" the brief asks for.

### Elements

| Element | Treatment |
|---|---|
| Panel frame | `Soot` at 0.94 alpha (the HUD uses 0.76), 1 px `Iron` border, 2 px radius, 10 px shadow. A 1 px title rule with five short ticks at its left end, borrowed from the compass bezel. |
| Background | A flat 35 % black scrim over the world. The world stays visible and moving on both sides of a centred sheet. No blur. |
| Typography | Barlow Condensed SemiBold capitals for titles, section heads, labels and keys; Barlow Medium for reading; Barlow SemiBold for values. Tabular figures. |
| Section headers | 17 px condensed capitals in `Brass` with an optional muted note beside them, over a 1 px `Iron` rule. This is the DS popup pattern, which already grew out of the HUD. |
| Separators | 1 px `Iron` rules between sections, and 24 px of space between groups. No boxes inside boxes. |
| Buttons | Dark warm fill, 1 px `Iron` border, 2 px radius, 40 px tall, condensed capitals. Primary actions carry an `Ember` border and label. Destructive actions are quiet until hovered, then take a `Wound` border. |
| Selected / focus | Focus: a 2 px `Ember` outline (the HUD's active-slot frame). Selected or current: an ember-tinted fill with a 3 px `Ember` bar on the left edge. The two can coexist on one row. |
| Disabled | Text at `Muted` 60 %, border at 40 %, and the reason always written beside the control, never only in a tooltip. |
| Warnings / refusals | A callout row: a 3 px left bar plus text, `Wound` for a refusal or a harm, amber `Ember` for a caution. The authority's sentence is shown verbatim. |

| Progress | A segmented gauge, the HUD's: an 8-10 px track with ticks every 10 %. The fill uses the semantic colour - pools their own, XP `Brass`, skill progress `Brass`, time left `Ash`. |
| Inventory rows | The HUD's framed icon slot at 36 px, name in bone, count and slot as chips, actions right-aligned as compact buttons, Drop last and quiet. |
| Stat values | A muted small-capital label beside a bone SemiBold value, right-aligned in a fixed cell - the pools panel's pattern. |

| Modal placement | Centred in the band the HUD leaves free (x 384-1536, y 128-848) and anchored at the top, so every title lands in the same place. |

### Advantages

- One product: the menus and the HUD share every token, so they need no reconciliation pass later.
- Consistent with the owner-approved doc 09 §9 direction, and with the blind review that preferred the production HUD in every run.
- The cheapest path. The tokens, the fonts and the key-cap, chip and slot patterns already exist and are proven at 1280x720 through 3440x1440.
- Restrained, so content and the world carry the identity. Nothing will date quickly.

### Risks

- **Soot and ember can drift into generic dark-fantasy survival UI** if ember spreads. The rule that prevents it: ember marks only focus, the primary action and things that need the player. Section heads are brass, values are bone, and large surfaces stay neutral.
- It is the "strange" axis of the brief that A expresses least. Its strangeness is quiet: instrument ticks, measured readouts, and magic channels sharing one gauge with health. A stronger strangeness can come later through world-specific icons, not chrome.
- It inherits the HUD's warm cast. If the art direction moves cooler, both must move together. That is a benefit as much as a risk.

### Godot difficulty

Low. Everything is `StyleBoxFlat`, `StyleBoxLine`, `Theme` colour, font and size items, `FontVariation` for spacing, and the existing slot shader. The title-rule ticks are one tiny `Control` with `_Draw` (five lines). The segmented gauge is the HUD's own.

### How it expresses science-fantasy

Through measurement. The interface reads as a frontier field instrument: engraved small-capital labels, tabular readouts, tick-ruled gauges and a bezel mark. It measures a world in which Focus, Strain and Resonance are quantities as real as Health and carrying weight. There is no parchment and no hologram: the same instrument reads both kinds of thing.

## Cross-cutting findings (all screens)

1. **Panels cover the HUD vitals while the world keeps running.** Character, Skills, Reputation, Effects, Companions and Building use an 800x760 panel at (60, 140), so they end at y = 900; Help ends at y ~1018. The vitals bars sit at x 24-344, y ~863-960 (`Hud.cs`: `vitals.Position = (24, -262)`). Every one of those captures shows the health/stamina bars half-hidden under the panel. With no true pause, a player reading their sheet can be hit and not see it. This is the most important functional defect in the presentation, not a cosmetic one. It gets worse at combination: the production HUD's pools panel is larger (x 28-482, y ~868-1050) and its combat log sits bottom-right (x ~1438-1890), and the 800 px panels at x 60 cover both the pools and, on Help, the log's left edge.
2. **Four unrelated geometries.** 800 wide at (60,140) (eight screens); 620+460 at (60,250) (Inventory); 820 centred with a full-screen shade (Saves); ~1206 at (60,110) (Help). Heights are fixed 760, hug-content, or fixed 420-scroll, at random.
3. **No theme at all.** Default Godot grey translucent `PanelContainer`, default font, default buttons. Only Saves has a scrim; only Help colours its headings; only Saves has a margin container. Nothing is shared.
4. **Text is a report, not an interface.** Character, Skills, Reputation, Effects, Companions, Building, Journal and part of Settings are a single `Label` holding one long string from the model's `Render()`. Headings, values and explanation are the same size and colour; hierarchy exists only as CAPS and two-space indents.
5. **Column alignment is faked with spaces in a proportional font** (`UiText.Column` pads with spaces). Values do not line up: Might/Endurance/Will, every Skills row, the Building catalogue.
6. **Developer vocabulary leaks to the player:** raw content IDs (`skill.one_hand_blade`, `ability.blade.force_cut needs skill.force 3`), raw slot keys (`main_hand`), world coordinates as a companion's location, "ticks", "Phase 1", "the authority's answer". The honesty is deliberate and good; the vocabulary is not player-facing.
7. **Title conventions differ on every screen:** `CHARACTER   [K] close`, `[Tab] close   Carried 3.7 / 50 kg ...` (no title), `Load a save   [L] or Escape: back to the game`, `CONTROLS   [F1] close`, `WHAT IS ON YOU` (the menu calls it Effects). Close hints are prose in the title string.
8. **Empty states look broken.** Effects and Companions show one sentence in the top-left of an 800x760 grey box; Journal shows a thin strip; Saves shows "No saves yet." over a 420 px empty scroll. Four different empty treatments, none intentional.
9. **No visible keyboard focus**, and Inventory buttons are `FocusMode.None` - not reachable without a mouse. Nothing is structurally controller-friendly yet.
10. **Text size floor is too low** for a 0.667x scale at 720p: Inventory rows 16, Help 17, footers 15.

# 01 - Shared UI language

## Where it lives

| File | What changed |
|---|---|
| `src/Presentation/Ui/HudStyle.cs` | +6 lines: the two approved additions only - `Coal` (0.085, 0.083, 0.078) for the secondary surface, idle button fill, hover and inset, and `Lichen` (0.56, 0.74, 0.47) for positive / available / READY. Nothing else in `HudStyle` changed; `HudStyle.Theme` (the HUD's own theme) is untouched. |
| `src/Presentation/Ui/UiKit.cs` | New. The one menu `Theme` plus the stateless factories. |
| `src/Presentation/Ui/HudView.cs` | Unchanged. `HudView.KeyCap` and `HudView.Gauge` are reused as they are. |

There is no `MenuStyle`, and no second palette, font set or gauge. Every colour is a `HudStyle` field (Soot, Track, Iron, IronBright, Bone, Ash, Muted, Ember, Brass, Wound, the pool fills, plus Coal and Lichen). Every face is `HudStyle.Body` / `Strong` / `Caps` (Barlow). Every key cap is `HudView.KeyCap`, every gauge `HudView.Gauge`, every chip `HudStyle.ChipBox`, every item slot `HudStyle.SlotBox` with `HudStyle.IconMaterial`.

## The theme (`UiKit.Theme`)

Built once from `HudStyle`, and set on each screen's root `Control` by `UiKit.Sheet`, because a `CanvasLayer` passes no theme down.

| Element | Treatment |
|---|---|
| Default | Barlow Medium 18, labels in Bone |
| Button | Barlow Condensed SemiBold 17; idle Coal fill + Iron border; hover IronBright border; pressed Ember 0.20 fill; disabled Muted at 0.55 on a dimmed Coal; keyboard focus a 2 px Ember outline (its own stylebox, drawn over any state) |
| `Primary` variation | Ember label and border (at most one a screen) |
| `Destructive` variation | Ash label, quiet; Wound label and border on hover / focus |
| `ListRow` variation | no frame until hovered (Coal) or pressed; focus outline as above |
| Selected / current | `UiKit.Select`: Ember 0.12 fill + 3 px Ember left bar - distinct from the focus outline |
| OptionButton / CheckButton | the button boxes, Barlow Medium 17 |
| PopupMenu | Soot 0.98 panel, Iron border; hover Coal with an Ember edge and Ember text |
| HSlider | Track groove with an Iron edge, Brass fill, Ember focus outline |
| VScrollBar | thin Track gutter, Iron grabber, IronBright on hover, Brass while dragged |

Button labels keep the model's own wording and case (Barlow Condensed is the "caps face"; the words are not upper-cased), so no label text changes and the existing harnesses that find buttons by their text still find them.

## The kit (`UiKit`)

| Part | What it is |
|---|---|
| `Sheet` | Full-screen root with the 35 % black scrim (the world behind takes no clicks); the sheet in the band, kept clear of HUD elements that reach into it (below what hangs in from above, above what rises from below, narrowed and centred around what stands beside it) - centred, top 128, width 640 / 880 / 1152, Soot 0.94, Iron hairline, padding 24; the 56-high title bar (title in condensed capitals 30, then the screen's own key cap if it has one, then the live `system_menu` key cap and CLOSE); the 1 px Iron rule with five bezel ticks; the optional 16 hint; the body. A scrolling body hugs its content up to the 720 band and scrolls under the fixed title bar beyond it; `Shape(width, dense)` switches template (the dense one is fixed 1152 x 720). |
| `Section` | Brass condensed-capital head 18, content 8 below |
| `Stat` | Muted condensed-capital label 16 left, value right (20 by default) in a given colour |
| `Gauge` | `new HudView.Gauge(...)` at a size |
| `Chip` | `HudStyle.ChipBox` + a condensed-capital word 16; the word is always there, so colour never carries state alone |
| `KeyCap` | `new HudView.KeyCap(HelpPanel.Key(action), 16)`, or nothing when the action is unbound |
| `Row` | The shared row: left slot or chip, middle name (Barlow SemiBold 18) over a secondary line (Ash 16), right side appended by the caller |
| `ListRow` | The same grammar inside a focusable `ListRow` button, for list panes |
| `Action` | Button 40 high (32 compact), focusable, Normal / Primary / Destructive, optional stable id |
| `Callout` | Coal box with a 3 px left bar in a tone (Wound for refusals, Ember for needs-the-player, Iron for a plain fact) |
| `EmptyState` | Condensed-capital head, one sentence, optional hint |
| `ListDetail` | 368 list, Iron divider in a 33 gutter, 703 detail; one `ScrollContainer` each, `FollowFocus` on |
| `Id` / `FocusedId` / `Refocus` | A stable id in node metadata, so a rebuilt screen returns the focus to the same thing |
| `Clear` | Remove-then-free, so a rebuild never finds last frame's rows |
| `TickRule` | The ticked rule under the title bar |

It holds no game state and has no animation, skinning, navigation stack, dependency injection or controller layer. The only static it keeps is the built `Theme` (an immutable resource cache, as `HudStyle` already does for its fonts).

## Relationship to the HUD

The HUD stays visible and live. Panels draw over the HUD where they meet (seen natively: a wide sheet hid the right of the companion strip), so the sheet keeps clear of any HUD element in the band rather than relying on draw order; it re-checks twice a second while open. No HUD element, position, size, typeface, colour or opacity changed; `HudView.cs` has no diff. Menus are the HUD's larger sibling: Soot at 0.94 instead of 0.76, a type step larger, with interactive states the HUD does not need.

# 03 - Keyboard and focus

Native, 1920x1080, committed DLL `ea197e9b…` (`receipts/1920x1080_report.json`, `final_1080_summary.txt`).

## Method

Arrow keys and Enter only, sent as real `InputEventKey`s. For each screen the walk starts at the screen's default focus and, for every control it reaches, replays the key path from the default focus and then tries Down, Right, Up and Left. Replaying matters: moving the focus onto a list row selects it and redraws the detail, as it does for a player. Left / Right are not pressed on a slider (they change its value). Tab is not used: in this game Tab is the Inventory key.

## Results

| Screen (state) | Default focus | Reached / focusable |
|---|---|---|
| System Menu | Continue | 13 / 13 |
| Character (a point to spend) | `+1 Might` | 3 / 3 |
| Character, Effects, Journal, Companions, Reputation (new game) | none - nothing to focus | 0 / 0 |
| Skills | the selected discipline | 11 / 11 |
| Inventory (new game, pack) | first button (Use) | 5 / 5 |
| Inventory (fixture, pack) | first button | 14 / 14 |
| Inventory (station) | first button | 11 / 11 |
| Building (new game) | selected row | 2 / 2 |
| Building (pieces and audit) | selected row | 12 / 12 |
| Companions (an order to give) | Follow me | 1 / 1 |
| Journal (one quest) | the selected quest | 1 / 1 |
| Settings | Look sensitivity | 5 / 5 |
| Save / Load (in play) | Back to the game | 2 / 2 |
| Help | none (read-only) | 0 / 0 |

Every focusable control on every screen is reachable from the keyboard alone. Keyboard-only route: Escape -> System Menu with Continue focused -> Down -> Character -> Right -> Journal -> Left -> Enter opened Character; Escape closed it to play.

## Focus, selection and disabled are distinct

- Focus: a 2 px Ember outline, its own stylebox, drawn over whatever state the control is in.
- Selected / current: an Ember 0.12 wash with a 3 px Ember left bar (list rows; the companion order already given). Visible side by side in `1920x1080_Companions_populated.png` (Wait here selected, Follow me focused) and in the Skills and Building captures (the selected row keeps its bar when focus moves to the detail).
- Disabled: Muted label at 0.55 on a dimmed fill, with the reason written beside it (the System Menu writes the model's hint; Make is disabled when the inputs are short, with "from … (N carried)" on the row).
- Primary (Ember label and border) is used at most once a screen.

## Focus kept across live rebuilds

Screens that redraw while open (Inventory after an item event, Building and Companions after a command or a refusal, Skills / Journal on selection, Character after a spend) record the focused control's stable id and give the focus back to the same control. Live values (effect time and gauge, companion health and downed countdown) update in place without a rebuild.

## Escape

Unchanged C4 semantics, verified natively on all twelve screens: with a screen open, Escape closes it to play (no stack, nothing reopens the menu); with nothing open, Escape opens the System Menu. Direct keys K, P, I, J, L and F1 open their screens and Escape closes them.

## Note

Arrow keys are also the movement keys. Management screens ignore movement, except an Inventory opened on a container (looting allows walking, unchanged from C4): there, arrow keys both move focus and walk. Recorded, not changed.

/// <summary>

{
    public const float Small = 640, Standard = 880, Wide = 1152;

    /// <summary>What a stable focus id is stored under, so a rebuilt screen can hand focus back to the same thing.</summary>

    /// <summary>The one menu theme, built from <see cref="HudStyle"/>; set on each sheet's root because a CanvasLayer passes none down.</summary>

    private static Theme BuildTheme()
    {
        var theme = new Theme { DefaultFont = HudStyle.Body, DefaultFontSize = 18 };
        theme.SetColor("font_color", "Label", HudStyle.Bone);
        theme.SetStylebox("panel", "PanelContainer", new StyleBoxEmpty());
        theme.SetStylebox("panel", "ScrollContainer", new StyleBoxEmpty());
        theme.SetStylebox("focus", "ScrollContainer", new StyleBoxEmpty());

        var disabled = new Color(HudStyle.Muted, 0.55f);
        foreach (string type in new[] { "Button", "OptionButton", "CheckButton" })
        {
            theme.SetFont("font", type, type == "Button" ? HudStyle.Caps : HudStyle.Body);
            theme.SetFontSize("font_size", type, 17);
            foreach (string state in new[] { "font_color", "font_hover_color", "font_focus_color", "font_pressed_color", "font_hover_pressed_color" })
                theme.SetColor(state, type, HudStyle.Bone);
            theme.SetColor("font_disabled_color", type, disabled);
            theme.SetStylebox("normal", type, Box(HudStyle.Coal, HudStyle.Iron));
            theme.SetStylebox("hover", type, Box(HudStyle.Coal, HudStyle.IronBright));
            theme.SetStylebox("pressed", type, Box(new Color(HudStyle.Ember, 0.2f), HudStyle.IronBright));
            theme.SetStylebox("hover_pressed", type, Box(new Color(HudStyle.Ember, 0.2f), HudStyle.IronBright));
            theme.SetStylebox("disabled", type, Box(new Color(HudStyle.Coal, 0.55f), new Color(HudStyle.Iron, 0.3f)));
            theme.SetStylebox("focus", type, Focus());
        }

        // One primary action a screen: ember label and border. Destructive: quiet until the pointer or the focus is on it.
        theme.SetTypeVariation("Primary", "Button");
        foreach (string state in new[] { "font_color", "font_hover_color", "font_focus_color", "font_pressed_color", "font_hover_pressed_color" })
            theme.SetColor(state, "Primary", HudStyle.Ember);
        theme.SetStylebox("normal", "Primary", Box(HudStyle.Coal, HudStyle.Ember));
        theme.SetStylebox("hover", "Primary", Box(new Color(HudStyle.Ember, 0.08f), HudStyle.Ember));
        theme.SetTypeVariation("Destructive", "Button");
        theme.SetColor("font_color", "Destructive", HudStyle.Ash);
        theme.SetColor("font_hover_color", "Destructive", HudStyle.Wound);
        theme.SetColor("font_focus_color", "Destructive", HudStyle.Wound);
        theme.SetStylebox("hover", "Destructive", Box(HudStyle.Coal, HudStyle.Wound));

        // A list row: no frame of its own until it is pointed at, chosen or focused.
        theme.SetTypeVariation("ListRow", "Button");
        theme.SetStylebox("normal", "ListRow", Box(new Color(0, 0, 0, 0), new Color(0, 0, 0, 0)));
        theme.SetStylebox("hover", "ListRow", Box(HudStyle.Coal, new Color(0, 0, 0, 0)));
        theme.SetStylebox("pressed", "ListRow", Box(new Color(HudStyle.Ember, 0.2f), new Color(0, 0, 0, 0)));
        theme.SetStylebox("hover_pressed", "ListRow", Box(new Color(HudStyle.Ember, 0.2f), new Color(0, 0, 0, 0)));

        theme.SetStylebox("panel", "PopupMenu", Box(new Color(HudStyle.Soot, 0.98f), HudStyle.Iron, 4));
        theme.SetStylebox("hover", "PopupMenu", Box(HudStyle.Coal, HudStyle.Ember, 2));
        theme.SetFont("font", "PopupMenu", HudStyle.Body);
        theme.SetFontSize("font_size", "PopupMenu", 17);
        theme.SetColor("font_color", "PopupMenu", HudStyle.Bone);
        theme.SetColor("font_hover_color", "PopupMenu", HudStyle.Ember);

        theme.SetStylebox("slider", "HSlider", Box(HudStyle.Track, HudStyle.Iron, 0, 3));
        theme.SetStylebox("grabber_area", "HSlider", Box(HudStyle.Brass, new Color(0, 0, 0, 0), 0, 3));
        theme.SetStylebox("grabber_area_highlight", "HSlider", Box(HudStyle.Brass, new Color(0, 0, 0, 0), 0, 3));

    /// <summary>Tag a control with a stable id, so focus can be handed back to it after a rebuild.</summary>
    public static T Id<T>(T control, string id) where T : Control
    {
        control.SetMeta(FocusKey, id);

    /// <summary>The stable id of whatever inside <paramref name="root"/> has the keyboard focus, or null.</summary>
    public static string? FocusedId(Control root)
    {
        var owner = root.IsInsideTree() ? root.GetViewport().GuiGetFocusOwner() : null;
        return owner is not null && root.IsAncestorOf(owner) && owner.HasMeta(FocusKey) ? owner.GetMeta(FocusKey).AsString() : null;
    }

    /// <summary>Give the focus to the control under <paramref name="root"/> tagged <paramref name="id"/>; false when none is.</summary>
    public static bool Refocus(Control root, string? id)
    {
        if (id is null)
            return false;
        foreach (var control in Controls(root))
        {
            if (control.HasMeta(FocusKey) && control.GetMeta(FocusKey).AsString() == id && control.FocusMode != Control.FocusModeEnum.None
                && control.IsVisibleInTree())
            {
                control.GrabFocus();
                return true;
            }
        }
        return false;
    }

    /// <summary>The first focusable, enabled control under <paramref name="root"/>, in tree order.</summary>
    public static Control? FirstFocusable(Control root) =>
        Controls(root).FirstOrDefault(c => c.FocusMode == Control.FocusModeEnum.All && c.IsVisibleInTree() && c is not BaseButton { Disabled: true });

    private static IEnumerable<Control> Controls(Node node)
    {
        foreach (var child in node.GetChildren())
        {
            if (child is Control control)
                yield return control;
            foreach (var deeper in Controls(child))
                yield return deeper;
        }
    }

    /// <summary>Remove and free every child, at once, so a rebuild never finds last frame's rows.</summary>
    public static void Clear(Node node)
    {
        foreach (var child in node.GetChildren())
        {
            node.RemoveChild(child);
            child.QueueFree();
        }
    }

/// <summary>
/// One management screen's frame. It holds only the nodes it made; what is drawn in the body is the screen's.
/// </summary>
public sealed class Sheet
{
    private readonly VBoxContainer _head = new();
    private readonly HBoxContainer _keys = new();
    private readonly CanvasLayer _layer;
    private string? _ownKey;
    private bool _closable = true;
    private bool _dense;

    /// <summary>Full screen: the scrim, and the control the menu theme hangs from.</summary>
    public Control Root { get; }

    /// <summary>The sheet in the band.</summary>
    public PanelContainer Panel { get; }

    public Label Title { get; }

    public Label Hint { get; }

    /// <summary>Where the screen draws.</summary>
    public VBoxContainer Body { get; }

    /// <summary>The body's scroll region, or null when the screen's panes scroll themselves.</summary>
    public ScrollContainer? Scroll { get; }

    internal Sheet(CanvasLayer layer, string title, string? ownKey, float width, bool scrolls)
    {
        _layer = layer;
        _ownKey = ownKey;
        Root = new Control { Theme = UiKit.Theme, MouseFilter = Control.MouseFilterEnum.Stop };
        Root.SetAnchorsPreset(Control.LayoutPreset.FullRect);
        var scrim = new ColorRect { Color = new Color(0, 0, 0, 0.35f), MouseFilter = Control.MouseFilterEnum.Ignore };
        scrim.SetAnchorsPreset(Control.LayoutPreset.FullRect);
        Root.AddChild(scrim);

        Panel = new PanelContainer { AnchorLeft = 0.5f, AnchorRight = 0.5f, GrowHorizontal = Control.GrowDirection.Both,
            GrowVertical = Control.GrowDirection.End, MouseFilter = Control.MouseFilterEnum.Stop };
        Panel.AddThemeStyleboxOverride("panel", (StyleBox)typeof(UiKit).GetMethod("SheetBox",
            System.Reflection.BindingFlags.NonPublic | System.Reflection.BindingFlags.Static)!.Invoke(null, null)!);
        var column = new VBoxContainer();
        column.AddThemeConstantOverride("separation", 16);

        _head.AddThemeConstantOverride("separation", 8);
        var bar = new HBoxContainer { CustomMinimumSize = new Vector2(0, 56) };
        bar.AddThemeConstantOverride("separation", 12);
        Title = HudStyle.Text(HudStyle.Caps, 30, HudStyle.Bone, caps: true);
        Title.Text = title;
        Title.VerticalAlignment = VerticalAlignment.Center;
        Title.SizeFlagsHorizontal = Control.SizeFlags.ExpandFill;
        Title.SizeFlagsVertical = Control.SizeFlags.Fill;
        bar.AddChild(Title);
        _keys.AddThemeConstantOverride("separation", 8);
        _keys.SizeFlagsVertical = Control.SizeFlags.ShrinkCenter;
        bar.AddChild(_keys);
        _head.AddChild(bar);
        _head.AddChild(new UiKit.TickRule());
        Hint = UiKit.Words(string.Empty, 16, HudStyle.Muted);
        Hint.Visible = false;
        _head.AddChild(Hint);
        column.AddChild(_head);

        Body = new VBoxContainer { SizeFlagsHorizontal = Control.SizeFlags.ExpandFill, SizeFlagsVertical = Control.SizeFlags.ExpandFill };
        Body.AddThemeConstantOverride("separation", 24);
        if (scrolls)
        {
            Scroll = UiKit.Scroll();
            Scroll.AddChild(Body);
            column.AddChild(Scroll);
            Body.MinimumSizeChanged += Refit;
            Body.Resized += Refit;
        }
        else
        {
            column.AddChild(Body);
        }
        Panel.AddChild(column);
        Root.AddChild(Panel);
        layer.AddChild(Root);
        Shape(width);
        Keys();
        layer.VisibilityChanged += () =>
        {
            if (layer.Visible)
            {
                Keys();
                Refit();
            }
        };
    }

    /// <summary>Change the template: the width, and whether the sheet is the dense 720-high one.</summary>
    public void Shape(float width, bool dense = false)
    {
        _dense = dense;
        Panel.OffsetLeft = -width / 2;
        Panel.OffsetRight = width / 2;
        Panel.OffsetTop = UiKit.BandTop;
        Panel.OffsetBottom = UiKit.BandTop;
        Panel.CustomMinimumSize = new Vector2(width, dense ? UiKit.BandHeight : UiKit.MinHeight);
        Refit();
    }

    /// <summary>Change the title, the screen's own key, or whether <c>[ESC] CLOSE</c> is offered (the start screen has nothing to close to).</summary>
    public void Head(string title, string? ownKey, bool closable = true)
    {
        Title.Text = title;
        _ownKey = ownKey;
        _closable = closable;
        Keys();
    }

    /// <summary>The optional hint under the rule; empty hides it.</summary>
    public void SetHint(string text)
    {
        Hint.Text = text;
        Hint.Visible = text.Length > 0;
    }

    /// <summary>Run <paramref name="shown"/> each time the screen opens, after it has laid out: where default focus is given.</summary>
    public void OnShown(Action shown) =>
        _layer.VisibilityChanged += () =>
        {
            if (_layer.Visible)
                Callable.From(shown).CallDeferred();
        };

    private void Keys()
    {
        UiKit.Clear(_keys);
        if (_ownKey is not null && UiKit.KeyCap(_ownKey) is { } own)
            _keys.AddChild(own);
        if (!_closable || UiKit.KeyCap("system_menu") is not { } escape)
            return;
        _keys.AddChild(escape);
        var close = UiKit.Caption("Close");
        close.VerticalAlignment = VerticalAlignment.Center;
        _keys.AddChild(close);
    }

    private void Refit()
    {
        if (Scroll is null)
            return;
        Callable.From(Fit).CallDeferred();
    }

    /// <summary>Hug the content, up to the band's 720: the body scrolls beyond that, under the fixed title bar.</summary>
    private void Fit()
    {
        if (Scroll is null || !GodotObject.IsInstanceValid(Scroll))
            return;
        if (_dense)
        {
            Scroll.CustomMinimumSize = Vector2.Zero;
            return;
        }
        float chrome = 8 + UiKit.Padding + _head.GetCombinedMinimumSize().Y + 16;
        float room = UiKit.BandHeight - chrome;
        float wanted = Math.Min(Body.GetCombinedMinimumSize().Y, room);
        if (Math.Abs(Scroll.CustomMinimumSize.Y - wanted) > 0.5f)
            Scroll.CustomMinimumSize = new Vector2(0, wanted);
    }
}
